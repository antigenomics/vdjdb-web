# Data sources

Every dataset this repository reads or ships, where it came from, and how to regenerate it.

## `test/resources/database/` — VDJdb test fixture

**What it is:** a 2,000 row subset of the VDJdb database, checked into the repository.
**Provenance:** *derived*, not experimental — a deterministic subsample of the production database.
**Format:** two tab-separated files, `vdjdb.txt` (27 columns, 2,000 rows) and `vdjdb.meta.txt`
(27 rows, one per data column). The two must stay in lockstep: `VdjdbInstance` reads the meta stream
to build the schema and then adds the data rows against it, so a column added on one side without the
other fails at load.

**Why it exists:** `BaseTestSpecWithApplication` boots a Guice application. Without a local database
`Database` calls `new VdjdbInstance()`, which calls `Util.checkDatabase()` and downloads the whole of
VDJdb over the network before any assertion runs.

**Upstream:** the production database at `vdjdb@100.83.178.73:~/vdjdb_publish/vdjdb-db/`, mounted into
the application container at `/home/vdjdb/vdjdb-db/`.

That file is itself derived from the VDJdb release, most recently
`https://github.com/antigenomics/vdjdb-db/releases/download/2026-06-03/vdjdb-2026-06-03.zip`
(see `latest-version.txt` in the same directory), and a copy of the 2026-06-11 ZENODO build is
mirrored at
`https://huggingface.co/datasets/isalgo/airr_benchmark/tree/main/vdjdb/vdjdb-2026-06-11-ZENODO`
(locally at `~/hf/airr_benchmark/vdjdb/vdjdb-2026-06-11-ZENODO/`).

⚠️ **Neither upstream is the direct parent of the fixture.** The released and mirrored files carry
**22 columns**; production carries **27** — it adds `evidence.validation.same.study`,
`evidence.validation.independent`, `evidence.structure.contacts`, `evidence.structure.quality` and
`evidence.structure.native`. Those five are generated by a step I could not locate in this repository
or on the server (`~/data_prep/concat_for_release.ipynb` is the closest candidate and was not
confirmed). **The fixture was taken from production because that is the only place the 27-column form
exists.** If you need to rebuild it from a public source, that missing step has to be identified
first — do not substitute the 22-column release, as the meta file and every `evidence.*` filter
expect 27.

**Regenerate:**

```bash
# On the server, or anywhere holding the 27-column vdjdb.txt + matching vdjdb.meta.txt.
SRC=/home/vdjdb/vdjdb_publish/vdjdb-db
TOTAL=$(($(wc -l < "$SRC/vdjdb.txt") - 1))
STEP=$((TOTAL / 2000))

# 1. Uniform spread, header included.
awk -v step="$STEP" 'NR==1 || (NR-1) % step == 0' "$SRC/vdjdb.txt" > vdjdb.txt

# 2. Top up high-confidence rows to 150 - SearchTableSpec pages a "vdjdb.score >= 3" result set at
#    page size 100 and asserts page 0 is full, and step 1 yields only ~89 such rows.
HAVE=$(awk -F'\t' 'NR>1 && $14==3' vdjdb.txt | wc -l)
awk -v step="$STEP" -v need="$((150 - HAVE))" -F'\t' \
  'NR>1 && (NR-1) % step != 0 && $14==3 && n < need { print; n++ }' "$SRC/vdjdb.txt" >> vdjdb.txt

cp "$SRC/vdjdb.meta.txt" vdjdb.meta.txt
```

Every Nth row rather than the head: the source is grouped by reference, so the first 2,000 rows would
be almost entirely one study. Deterministic on purpose — a fixture that resampled per run would make
a test failure impossible to reproduce.

⚠️ **The result is deliberately not distributionally faithful** — step 2 over-represents
`vdjdb.score = 3` roughly fourfold. It is a fixture for exercising code paths, not a sample to measure
anything on. One row appears twice, which is also true in the source.

See `test/resources/database/README.md` for the coverage the current specs depend on.

## `application.database.path` — runtime VDJdb

**Production:** `~/vdjdb_publish/vdjdb-db/` on the deployment host, bind-mounted read-only to
`/home/vdjdb/vdjdb-db/` (see `docker-compose.yml`). Alongside `vdjdb.txt`/`vdjdb.meta.txt` it holds
`cluster_members.txt` and `cluster_members_tcremp.txt` (TCRNET and TCREMP motif cluster membership),
`motif_pwms*.txt`, `structures_metadata.tsv`, and `motif-charts/`.

**Development:** `database/` relative to the working directory, per `conf/application.conf`. Absent by
default; the application downloads a release into `~/.vdjdb` when it is missing.

## `app/backend/.../demo` — demo dataset

**Production:** `~/vdjdb_publish/demo/`, bind-mounted to `/home/vdjdb/demo-dataset/`, served by
`AnnotationsAPI` for the "Download an example sample" link. VDJtools-format TRB repertoires.
